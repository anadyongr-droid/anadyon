## Then Tasos widened it: every principle binds, without exceptions

The §13 fix above treated one symptom. Tasos's instruction was that **all** the
project's principles bind, for all agents, non-stop and without exceptions —
which the AGENTS.md entry alone does not achieve, because the underlying problem
is that `DEFINING-STATEMENTS.md` never loads.

Checked: of the thirteen principles, **five were cited nowhere in AGENTS.md** —
§1, §2, §3, §5 and §6. Among them *"Pricing is calculated in one place"* and
*"Customer data is not exposed by default"*. An agent could work for a week
without ever being shown either.

**`CLAUDE.md` now imports both files.** That is the structural fix: every
principle enters every agent's context, every session, with nothing left to
remember or go looking for. The cost is about 34 KB, which is the cheapest part
of any session.

Summarising the principles into AGENTS.md was the alternative and is worse — a
summary drifts from what it summarises, and the drift is invisible precisely
because the summary reads fine.

`lib/governanceWiring.test.ts` asserts the wiring: that CLAUDE.md still pulls in
AGENTS.md, that every `§N` AGENTS.md cites exists, and that §13 is visible by
number *and* by substance — a bare "§13" left behind while the paragraph around
it was deleted would satisfy a reference check and teach an agent nothing.
Confirmed to fail against yesterday's AGENTS.md before being trusted.

Five assertions in total: that CLAUDE.md imports both files, that no principle
has been dropped or renumbered (a gap means a deletion, and a deletion that
renumbers its successors silently rewrites every reference to them elsewhere),
that every `§N` AGENTS.md cites exists, and that §13 is visible by number and by
substance. Each was confirmed to fail against the state it guards against before
being trusted.

What none of them can assert is obedience. They assert that an agent is *shown*
every rule before it acts, which is the part that actually failed.

## Audited all thirteen principles against the code

Loading them exposed §10's stale price within minutes, which argued for checking
the rest deliberately rather than finding them one at a time by accident. Six
are factually checkable; the other seven are process or design judgement.

**Three were wrong. One suspected fault was not.**

**§5 was stale and actively dangerous.** It said *"All price calculation happens
client-side in the booking form. The API formats and emails the values it is
given and never recalculates them."* `app/api/quote/route.ts:301` is headed
"Server-side verification — recalculate independently from DB" and computes
`serverVehicleSubtotal`, `serverTotal`, `serverDeposit`, `serverBalanceDue`. The
client's deposit is bound to `_clientDeposit` and discarded.
`docs/HANDOFF-H1.md` §7 already said *"the server's pricing always wins."*

Worse than an inaccuracy: §5 named the server implementation as the thing to
avoid — "no second implementation to drift out of step". An agent following it
faithfully would delete the recalculation, which is the **tamper-resistance
control** against a crafted request naming an expensive model at a cheap price.
Four tests in `lib/quoteTamperResistance.test.ts` hold it there. Rewritten to
describe what is actually true: one module, two callers, server authoritative.

**§6 was overstated.** *"Tables are never granted to the anonymous role"* —
migration 023 deliberately grants `select` on `rates` and `extras_config`,
because the public form cannot price a rental without them and neither holds a
customer record. An absolute the codebase knowingly breaks is worse than a
precise rule: an agent correcting the code toward it revokes the grants and
breaks public booking. Narrowed, and the grant/policy distinction spelled out —
`001_baseline.sql` creates several policies `to anon` that are inert because the
grant was revoked, which reads like exposure and is not.

**§1 is wrong and I did not fix it.** It claims *"In practice: sources at
~1600px"*. Measured: `fiat-panda.jpg` 300×185, `giant-bike.jpg` 516×387,
`hero-zakynthos.jpg` 1200×800. Correcting the document is the option that
silently accepts worse photographs, so it is **W18** for Tasos: re-source the
images, or lower the stated standard. Not an agent's call.

**§4 checked out.** An early grep suggested `flight_number` was collected but
not stored — a defect §4 names explicitly. It searched only `001_baseline.sql`;
migration 007 adds the column to both `quotes` and `reservations`. No finding,
and worth recording that the false alarm came from searching one file instead of
the schema.

§2, §3 and §7–§13 show no contradiction with the code.

**The pattern across §1, §5, §6 and §10 is the same:** each stated something
absolutely or numerically, the code diverged for good reasons, and nobody
noticed because nothing read the file. They were harmless while unread. They
became live the moment CLAUDE.md began importing them — which is the argument
for the import, not against it.
