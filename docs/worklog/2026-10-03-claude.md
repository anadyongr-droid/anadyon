## Tier 1 of the agent-oversight work: production is denied, and it was fired to prove it

Built and verified. Runbook **section 16** owns the subject; this records the day.

**Two corrections to my own proposal, made before writing code.** I had called
this "ten minutes" for both agents. It is, for Codex. It is not for Claude Code:
the OS-level block needs `sandbox.enabled`, and the sandbox's allowed-domain list
**starts empty**, so switching it on repository-wide would break `npm ci` for
every agent on the next run. The right mechanism without the sandbox is
`permissions.deny`, which also covers WebFetch — something the sandbox explicitly
does *not*. Sandboxing is recorded as **not done**, with the allowlist work named,
rather than claimed as part of this.

**And I nearly built a parallel source of truth.** `scripts/deployment-boundary-lib.mjs`
already owned `STAGING_PROJECT_REF`; I was about to add a new JSON file of project
identifiers beside it, which is §9's exact failure mode. Extended that module
instead — it now exports `PRODUCTION_PROJECT_REF` and `PRODUCTION_DENY_HOSTS`.

**Something that turned out to be already done**, per §11.1: the same module
already refuses a staging deploy carrying a non-`sk_test_` Stripe key. That was
one of the three risks in the proposal and it has been enforced for some time.

**Verified by firing the rules, not by reading the config.** Immediately after
they landed, in this session:

| Attempt | Result |
|---|---|
| WebFetch to the production host | `WebFetch denied access to domain:idfavwwfiuncoudkcfsp.supabase.co.` |
| `curl` to the same host | `Permission to use Bash … has been denied.` |
| WebFetch to the **staging** host | **HTTP 401** — still reachable |
| `grep <prod ref> docs/audits/…` | ran normally |

**The last two rows are the whole point.** A blanket deny would have passed the
first two and broken every legitimate task — and the staging-ref assertion in
`tests/agentNetworkControls.test.ts` exists because denying the wrong half of a
copied pair would look like a working control while leaving production reachable.
The fourth row validates a specific design choice: the Bash rules name a program
(`curl`, `psql`, `supabase link`) rather than matching the bare ref, because
`Bash(*<ref>*)` would have blocked the grep that audits the rule. A control that
blocks its own review is one nobody can check.

Fail-first: the test failed on three assertions against the unprotected settings
before the rules existed.
