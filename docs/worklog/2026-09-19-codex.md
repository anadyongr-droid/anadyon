Reconciled the stale `claude/phase2-correct-void` branch with `main` in an
isolated worktree. The only textual merge conflict was the rental-system
blueprint; the current 19 September material was retained and the branch's
counter HTTP and correction/voiding decisions were added after it.

The branch now contains:

- migration 043, which implements handover correction and voiding;
- the five staff handover HTTP routes and their route tests;
- migration 045, which grants the four identity-verifying handover gateways to
  `authenticated` only; and
- route changes that call those gateways through the user's cookie-backed
  Supabase session rather than calling the privileged implementations through
  `service_role`.

That last change is the closed identity decision from
`OPEN-QUESTION-RPC-STAFF-IDENTITY.md` §13.4 made executable: the database sees
`auth.uid()` and verifies the current server-owned role itself. `anon`,
`service_role` and `PUBLIC` remain unable to execute the gateways. The
implementation functions remain available only to `service_role` for existing
server-side compatibility.
