## W56: a read-only production query, built and deliberately not merged

Tasos challenged the previous review's dismissal of per-endpoint policy tooling:
if a control lets an agent do more of the work, its **throughput** value counts
as much as its safety value. He was right that I had weighed only the latter.

So I measured instead of arguing. On 4 October, **five round trips** asked him to
paste a read-only query into the dashboard and type the answer back: the pgaudit
status, the `pg_db_role_setting` row, the `quotes` diagnostic, the 048
verification, and one repeat. Every one was a SELECT. A sandbox or a policy layer
would not have removed a single one — the work was never blocked by shell policy.
It was blocked by **an agent having no way to read production.**

`.github/workflows/production-query.yml` is the narrowest thing that closes it:

- the credential stays in Actions secrets, where neither agent can read it;
- `default_transaction_read_only` is set at the **server**, so a file edited to
  write is refused by Postgres rather than by our opinion of it;
- the input is a **bare file name inside `scripts/sql/readonly/`** — a path or
  `..` is refused — so every question an agent asks of production is committed,
  diffable and reviewable. That is *better* accountability than dictating ad-hoc
  SQL into somebody's clipboard, not worse;
- `tests/productionQuery.test.ts` fails if any file in that directory contains a
  writing verb.

It cannot write, cannot apply a migration, and **does not change who may** —
that is `AGENTS.md`'s rule and W38's decision, not a workflow's.

**Left unmerged on purpose.** It widens what an agent may do against production,
and §13's spirit is that a proposal is not a deployment even when the proposal is
mine. Tasos approves the merge or does not.

One honest note on my own test: the first version asserted that 400 rows of
output would overflow ten annotations. It fits. The test failed on correct code
and I fixed the arithmetic, not the code — the same shape as a repro that cannot
exhibit the bug, which `AGENTS.md` warns about by name.
