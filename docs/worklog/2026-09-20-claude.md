## Wired §13 into the file agents actually read

Tasos asked on 20 September whether the 19 September rollback and the new
principle had both been done. Checked, and reported: the rollback was complete —
customer-facing copy is byte-identical to its state before the change, verified
by diff rather than taken on trust, and W11–W13 stayed open so the underlying
defects were not quietly closed along with the wording. `DEFINING-STATEMENTS.md`
§13 was written and is thorough.

**But it did not bind.** `CLAUDE.md` is one line, `@AGENTS.md`, so AGENTS.md is
the only document loaded into an agent's context automatically.
`DEFINING-STATEMENTS.md` is not. AGENTS.md had no reference to §13, and still
carried its own instruction to decide *"whether a design is significant enough
to check"* — the exact judgement §13 removes. An agent starting fresh would read
the licence and never see the limit.

Three changes, all to AGENTS.md:

- **"The default is to act" is now qualified** where §13 overrides it, with the
  19 September incident named as the reason. The rest of that section stands —
  the default was about how a thing is built, not about what Anadyon sells.
- **"What still comes back" gains an entry** covering prices, insurance wording,
  eligibility rules, customer text, staff authority and products, pointing at
  §13 for the full scope and stating what does *not* count as approval.
- **The "not on the list" paragraph loses one clause**, and says so rather than
  quietly dropping it, so a reader who remembers the old wording can see what
  changed and why.

Tasos approved these three and then asked for more — see below.

## Then Tasos widened it: every principle binds, without exceptions

The §13 fix above treated one symptom. Tasos's instruction was that **all** the
project's principles bind, for all agents, non-stop and without exceptions —
which the AGENTS.md entry alone does not achieve, because the underlying problem
is that `DEFINING-STATEMENTS.md` never loads.

Checked: of the thirteen principles, **five were cited nowhere in AGENTS.md** —
§1, §2, §3, §5 and §6. Among them *"Pricing is calculated in one place"* and
*"Customer data is not exposed by default"*. An agent could work for a week
without ever being shown either.

**`CLAUDE.md` now imports both files.** That is the structural fix: every
principle enters every agent's context, every session, with nothing left to
remember or go looking for. The cost is about 34 KB, which is the cheapest part
of any session.

Summarising the principles into AGENTS.md was the alternative and is worse — a
summary drifts from what it summarises, and the drift is invisible precisely
because the summary reads fine.

`lib/governanceWiring.test.ts` asserts the wiring: that CLAUDE.md still pulls in
AGENTS.md, that every `§N` AGENTS.md cites exists, and that §13 is visible by
number *and* by substance — a bare "§13" left behind while the paragraph around
it was deleted would satisfy a reference check and teach an agent nothing.
Confirmed to fail against yesterday's AGENTS.md before being trusted.

Five assertions in total: that CLAUDE.md imports both files, that no principle
has been dropped or renumbered (a gap means a deletion, and a deletion that
renumbers its successors silently rewrites every reference to them elsewhere),
that every `§N` AGENTS.md cites exists, and that §13 is visible by number and by
substance. Each was confirmed to fail against the state it guards against before
being trusted.

What none of them can assert is obedience. They assert that an agent is *shown*
every rule before it acts, which is the part that actually failed.

## Loading the principles immediately found a wrong one

The moment `DEFINING-STATEMENTS.md` began loading, §10 turned out to say the
Full Damage Waiver *"is sold at €12 a day"* — the figure corrected to €5.00 on
19 September across five documents. So the import briefly made things worse:
a stale price that had been sitting unread became a stated principle in every
agent's context.

`lib/publishedPriceParity.test.ts`, written on 19 September to prevent exactly
this, did not catch it. It scanned `docs/`, and this file is at the repository
root. So did the manual grep that found the other five. **Both searched the
directory instead of the repository, and the control reported clean while the
most-read file in the project carried the error.**

The test now also scans `DEFINING-STATEMENTS.md`, `AGENTS.md`, `README.md` and
`CLAUDE.md`. Confirmed to fail on §10 before the correction and pass after.

One process note worth keeping. The first attempt at widening the scan silently
did not apply — the search string's indentation was wrong, the replacement was a
no-op, and the suite went green. It looked like proof the scan was clean. It was
proof of nothing. PR #95's notes record the same thing happening to a mutation
test; checking that the file actually changed is what caught it both times.
